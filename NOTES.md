# Примітки до лабораторної роботи №5

## Припущення

- Надані звіти ЛР №1–№4 окремими файлами у робочій теці відсутні. Тому точний контент та порядок видимих блоків взято зі скриншота макета й опису завдання; додані відгуки, міста та контактні дані є демонстраційними, а не реальними свідченнями клієнтів.
- SVG-активи та `image.webp` були у `assets/` робочої теки. Відеофайл, переданий окремо, збережено копією у `assets/video/hero-video.mp4`; вихідні файли не видалялися й не змінювалися.
- Вихідний `logotype.svg` має кремовий прямокутний фон, непридатний для темного header. Для сторінки створено окрему прозору жовту версію `logotype-header.svg`; початковий файл збережено без змін.
- Макет зображення WebP має декоративну ліву частину, тому його використано як poster hero-відео; під час відтворення відео відображається саме відео. Якщо потрібен статичний режим, варто підготувати окремий crop кадру із правої частини референсу.
- Точний склад питань квізу, прайсинг і політика підписки не надані; квіз лишається статичним, а посилання веде до контактної форми.
- Контактний email і телефон — тестові. Перед публікацією замініть їх на справжні.

## Відомі обмеження

- Google Fonts підключаються мережею; за відсутності мережі браузер використає системний sans-serif.
- Форма використовує `mailto:` як статичну демонстрацію, не має серверного обробника та не гарантує надсилання у всіх поштових клієнтах. Backend/обробку форми та повідомлення про результат треба реалізувати окремо.
- Відео запускається без звуку; у браузері, який блокує autoplay, доступний poster. Для користувачів із `prefers-reduced-motion: reduce` відео приховується.
- Перевірки контрастності виконано за вибором кольорів і структурою; для остаточного WCAG-звіту бажано перевірити всі комбінації у браузері/axe та перевірити клавіатурою.

## Що залишити для ЛР №6

- Виділити компоненти `Header`, `Hero`, `Button`, `Card`, `Navigation`, `Footer`.
- Визначити API компонентів і винести повторні стилі без зміни вигляду сторінки.
- Перевірити компоненти на різних даних та узгодити їхні стани.

## Запуск

Відкрийте кореневий `index.html` у браузері або запустіть VS Code Live Server з кореня проєкту. Для надійної перевірки autoplay, локального відео та шляхів бажано використовувати локальний HTTP-сервер.

## ЛР №10 — інтеграція бібліотек

- Використано Vanilla JS-плагіни замість jQuery: проєкт уже працює без jQuery, а потрібні компоненти мають власні API.
- CSS Swiper, Fancybox і AOS розміщено в `<head>`, аби стилі були доступні до відображення компонентів; JavaScript-бібліотеки та `js/plugins.js` завантажуються наприкінці сторінки після основного вмісту.
- Ініціалізація відбувається в `DOMContentLoaded`; перед запуском перевіряються наявність відповідного елемента та глобального об'єкта бібліотеки. Якщо CDN недоступний, ініціалізація пропускається без звернення до відсутніх API.
- У Swiper шість відгуків, щоб залишити достатній запас для `loop` на широкому екрані, де одночасно видно три слайди.
- AOS застосовано до заголовків і контейнерів, але не до `.swiper-slide`: Swiper сам керує transform слайдів.
- `prefers-reduced-motion` вимикає анімацію Typed.js та автопрокручування Swiper; AOS також вимкнено для цього режиму. Статичний слоган залишається доступним.
- Усі опції з заданої конфігурації збережені; опції, що потребують видалення через непідтримку, не виявлялися. Перевірку поведінки Fancybox, Swiper, Typed.js та AOS у браузері слід виконати вручну.
- Галерея повторно використовує наявний `assets/images/image.webp` у шести елементах із різними підписами; оригінал не змінювався. Нових зображень та інших бінарних файлів не додано.
